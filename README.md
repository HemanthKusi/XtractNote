# XtractNote

**AI-powered YouTube to content converter**: blog posts, study notes, summaries, research briefs, flashcards, quizzes and social posts from a video.

Paste a YouTube link and choose a format. The backend fetches the video's transcript and runs it through a staged pipeline built with LangGraph: the transcript is split into timed sections, analysed into an outline, and drafted into the chosen format. The steps run in a fixed order, and two of them call a model.

## Architecture

```
Frontend (Next.js + React)  ←→  Backend (Python + FastAPI + LangGraph)  ←→  Supabase (Auth + DB)
```

- **Frontend:** Next.js 16, TypeScript, Tailwind CSS, shadcn/ui
- **Backend:** Python 3.13, FastAPI, LangGraph, LangChain
- **Database:** Supabase (PostgreSQL + Auth + Storage)
- **AI:** OpenAI / Anthropic Claude (swappable via env variable)

## Getting Started

### Prerequisites

- Node.js 22.18+ (`node --version`) — 18 and 20 are both past end of life, and
  the toolchain already required newer than 18 regardless: Next 16 asks for
  20.9+, ESLint 10 for 20.19+, and the lint step reads TypeScript directly,
  which Node runs without a flag from 22.18
- Python 3.13 (`python --version`) — not 3.14, which has no `pydantic-core` wheels
- Git (`git --version`)
- A Supabase account (free at supabase.com)
- An OpenAI or Anthropic API key (at least one)
- A YouTube Data API key: the backend looks up each video's length to price a
  generation, and refuses without one

### Setup

```bash
# 1. Clone the repo
git clone https://github.com/YOUR_USERNAME/xtractnote.git
cd xtractnote

# 2. Set up the frontend
cd frontend
npm install --legacy-peer-deps
cp .env.example .env.local
# Edit .env.local with your Supabase keys
cd ..

# 3. Set up the backend (Python 3.13 specifically)
cd backend
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
# Edit .env with your keys
cd ..

# 4. Set up the database
# Run every file in database/ in the Supabase SQL editor, in numeric order
# (001 first). Migrations are applied by hand; the app never runs them.

# 5. Start both servers
# Terminal 1 — Frontend (http://localhost:3000)
cd frontend && npm run dev

# Terminal 2 — Backend (http://localhost:8000)
cd backend && source .venv/bin/activate && uvicorn app.main:app --reload --port 8000
```

### Environment Variables

Each app has its own template:
- `frontend/.env.example` → copy to `frontend/.env.local` (frontend variables start with `NEXT_PUBLIC_`)
- `backend/.env.example` → copy to `backend/.env` (backend variables, including secrets)

Each template lists the values that app needs. Both copies are gitignored.

## Development

- Frontend runs on `http://localhost:3000`
- Backend runs on `http://localhost:8000`
- API docs at `http://localhost:8000/docs` (auto-generated by FastAPI)

The checks a pull request into `develop`, `staging` or `main` must pass, and
how to run them locally from the repository root:

```bash
(cd frontend && npx tsc --noEmit && npm run lint && npm run build)
(cd backend && ./.venv/bin/python -m pytest)
```
